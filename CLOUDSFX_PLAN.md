# CloudsFX — a delay/granular **insert-FX** version of the Clouds port

Status: **IMPLEMENTED** (drumlogue delfx unit). This document originally
captured the design; the notes below record how it was actually built and
where the implementation deviates from the first sketch.

## As built

- **New files:** `clouds-fx.cc` (the FX engine: stereo in/out, chunks to 32,
  reuses the Clouds DSP) and `drumlogue_delfx_wrapper.cc` (the delfx `unit_*`
  callbacks). `header.c` gained a `#elif defined(CLOUDS_FX)` param block and a
  conditional `.target = … | k_unit_module_delfx`.
- **A separate `clouds-fx.cc` was used instead of an `#ifdef CLOUDS_FX` path
  inside `clouds-granular.cc`.** The synth file is tightly bound to the mono
  OSC synth model; a dedicated translation unit keeps the working synth build
  untouched and avoids cramming stereo-FX I/O into it. The two files are never
  linked together, so each keeps its own static engine/buffers with no ODR
  clash.
- **Parameters (11), per the user's decision** ("same params as the Clouds
  synth, minus the sample number/bank, since the stream comes from audio in"):
  Position, Size, Density, Texture, Pitch, Feedback, Dry/Wet, Reverb, Freeze,
  Mode, Quality. Base Note and all four sample params (SampleBank, SampleNum,
  SmplStart, SmplEnd) are dropped — they only fed the internal source. Dry/Wet
  defaults to 50% (an insert-FX default) rather than the synth's 100%.
- **No `osc_clouds_fx.mk`.** delfx units don't exist on the prologue-class
  platforms, so CloudsFX is drumlogue-only and is built through the SDK
  project `drumlogue/clouds_fx/` via `build_drumlogue.sh clouds_fx` (added to
  `ALL_PROJECTS` and regenerated by `generate_sdk_projects.sh`).
- **Verification:** `make test-clouds-fx` links the real Clouds engine through
  the delfx wrapper and asserts the delfx target/name/params, the Mode/Quality
  strings, dry-passthrough of the FX-bus input, and non-silent wet granular
  output. All existing suites still pass. As with the rest of the drumlogue
  port, the ARM/NEON firmware build and final level tuning are a hardware gate.

_Original design notes follow._

This documents how
to turn the Clouds granular engine into a drumlogue *effect* that granulates the
**incoming audio** on the FX bus, rather than an internally-generated source.

## Why it's a separate unit, not a mode of the existing Clouds

The current `Clouds` port is a **synth** unit:

```c
// header.c
.target = UNIT_TARGET_PLATFORM | k_unit_module_synth,
```

Synth units generate sound and their render callback ignores audio input — the
wrapper says so explicitly:

```c
// drumlogue_unit_wrapper.cc
void unit_render(const float *in, float *out, uint32_t frames) {
  (void)in;  /* synth units ignore input */
```

To process incoming audio, the unit must instead be a **delay-FX** unit
(`k_unit_module_delfx`). The drumlogue routes the FX-send bus into a delfx
unit's `unit_render(in, ...)` as interleaved stereo. The SDK already defines the
target we need:

```c
// drumlogue/runtime.h
k_unit_target_drumlogue_delfx = (4U << 8) | k_unit_module_delfx,
```

So CloudsFX is a **new build target** that reuses the same Clouds DSP engine
(`clouds/dsp/granular_processor.*`, already vendored and working) but wires the
FX-bus input into the engine's `ShortFrame input[]` instead of the internal
sawtooth/sample generator. The existing synth `Clouds` stays untouched.

This is squarely in Clouds' original nature: the hardware module **is** an audio
processor. The synth port only exists because it had to invent an input; as an
insert FX the input is real, so Freeze, Feedback, Dry/Wet, and the Looping-Delay
/ Stretch modes all become genuinely useful.

## Architecture

```
drumlogue FX bus (stereo float in)
      |  unit_render(in, out, frames)          <-- delfx callback
      v
drumlogue_delfx_wrapper.cc   (NEW - thin, stereo in/out, chunks to 32)
      |  clouds_fx_process(in_stereo, out_stereo, n)
      v
clouds-granular.cc  (guarded additions under #ifdef CLOUDS_FX)
      |  float->ShortFrame in, GranularProcessor::Process, ShortFrame->float out
      v
clouds/dsp/granular_processor.*  (unchanged submodule DSP)
```

The existing `drumlogue_osc_adapter.cc` is built around **output-only, mono**
synth voices, so CloudsFX should **not** reuse it. A small dedicated delfx
wrapper that talks to a new `clouds_fx_*` entry point in `clouds-granular.cc` is
cleaner than bending the mono OSC adapter to carry stereo input.

## Files to add / change

1. **`osc_clouds_fx.mk`** — new build config. Defines `-DCLOUDS_GRANULAR
   -DCLOUDS_FX -DOSC_NATIVE_BLOCK_SIZE=32`. For the drumlogue platform, uses
   `header.c` + a new `drumlogue_delfx_wrapper.cc` (instead of
   `drumlogue_unit_wrapper.cc` + `drumlogue_osc_adapter.cc`). Same Clouds DSP
   source list as `osc_clouds.mk`.
2. **`drumlogue_delfx_wrapper.cc`** — new. Implements the delfx `unit_*`
   callbacks. `unit_render` de-interleaves `in` into L/R, chunks to
   `kMaxBlockSize` (32), calls `clouds_fx_process`, re-interleaves to `out`.
   `unit_set_param_value` maps the CloudsFX param IDs to the engine.
3. **`clouds-granular.cc`** — add an `#ifdef CLOUDS_FX` path:
   - `clouds_fx_process(const float *in, float *out, uint32_t frames)`: convert
     float stereo `in` → `ShortFrame` (with input headroom), run
     `processor_.Prepare()` + `Process()`, convert `ShortFrame` out → float
     stereo. Keep the continuous-grain trigger (already added) so Granular mode
     stays smooth. Honor `dry_wet` (the engine already crossfades; with real
     input the dry path is finally meaningful).
   - Parameter setters shared with the existing OSC_PARAM cases where possible.
   - No Base Note / gate / sample-bank / sawtooth code in FX mode.
4. **`header.c`** — add `#elif defined(CLOUDS_FX)` block:
   - `.target = UNIT_TARGET_PLATFORM | k_unit_module_delfx`
   - `.unit_id = 'CLDX'`, `.name = "CloudsFX"`
   - Params (proposed, ~11): Position, Size, Density, Texture, Pitch, Feedback,
     Reverb, Mix (Dry/Wet), Mode (Granular/Stretch/Delay/Spectral), Quality,
     Freeze. **No** Base Note / SampleBank / SampleNum / SmplStart / SmplEnd.
5. **`drumlogue/clouds_fx/`** + **`manifest_clouds_fx.json`** — new project dir
   and manifest with `"module": "delfx"`; add to the drumlogue packaging in the
   Makefile.
6. **`test_drumlogue_callbacks.cc`** — add a `CLOUDS_FX` branch: assert the
   delfx target and param names, plus a stereo passthrough test that feeds a
   known non-zero input and asserts a non-silent wet output (proves the FX-bus
   input actually reaches the engine — something the synth build can't test).

## Decisions to confirm before building

- **Param layout & defaults** — the ~11 proposed above; in particular whether to
  expose an internal **Mix/Dry-Wet** knob or rely on the drumlogue's own FX-depth
  control. (Recommend keeping an internal Mix mapped to the engine's `dry_wet`,
  since it also governs the wet feedback character.)
- **Freeze** — momentary vs. latched toggle (recommend latched on/off, matching
  the synth port).
- **Which Modes to keep** — all four are valid for an insert FX; *Looping Delay*
  and *Stretch* are the headline modes for this use case.
- **Input headroom** — Clouds sums overlapping grains; recommend ~−6 dB input
  trim + the existing output headroom to stay clear of clipping with live
  material.

## Notes / constraints

- The `eurorack/` submodule (Clouds DSP) is **not** modified — all additions live
  in the port layer, same rule as the rest of this repo.
- Firmware is ARM/NEON; this environment has no ARM toolchain, so the plan is
  validated by code inspection + native host tests (as done for the arpeggiator).
  A hardware smoke test on the drumlogue is the final gate.
- Estimated effort: ~1 focused implementation pass (new wrapper + header block +
  FX path in clouds-granular.cc + mk/manifest/project + tests), then a hardware
  check for levels and latency.
